# Windows movement compensation

The original CC0 [font recipe](font-recipe.json) and
[SVG](windows-movement.svg) isolate compensation for independent projection and
freedom vectors. Windows rounds each dot-product component independently. An
explicit `SFVTPV` copy selects unit compensation; later vector setters restore the
general path even when the component words remain equal. Horizontal signed
division, vertical rounding and exact-ratio placement remain distinct.

[Capture provenance](capture.json) pins three agreeing fresh healthy processes
per platform, plus positive missing/different-program controls. Numerical Windows
companions query the opposite coordinate and symmetric smoothing, with three
captures each. Their programs/gasp variant are recorded for recomposition. Together
the markers establish both coordinates without redistributing another font.
Linux light fitting retains its separate native image.

Eight direct [mechanisms](../../Lokad.Svg.Tests/TrueTypeHintingTests.WindowsMovement.cs)
protect the transitions, signed compensation, component rounding, original points,
touches and cleanup. Six fail against the previous implementation. One canonical
[rendering case](../../Lokad.Svg.VisualTests/SvgWindowsScanBoundaryTests.cs) covers
the supplied program on both platforms. Broad numerical probes remain research;
the API/ownership matrix and existing reference images are unchanged.
